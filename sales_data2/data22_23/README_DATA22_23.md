# data22_23 — the 2022–2023 dataset (subsequent load 1)

Continues [data18_21/](../data18_21/) into the endemic phase. Every file is named **exactly like
its counterpart there** with identical headers, so the same SQL\*Loader control files load it
unchanged, and every ID continues from where `data18_21` stopped — nothing collides.

Generated by [../gen_sales_data2.py](../gen_sales_data2.py) as part of the same world model, so the
14,632 existing customers keep transacting alongside the new ones, the staff who left in the
lockdowns stay gone, and the 2022 rehiring wave arrives here.

## Loading it

```
cd operational_DB\sqlloader_control_files
load_all.bat dwh <password> XE "<repo>\sales_data2\data22_23"
```

`supplier.csv` and `branch_utils_category.csv` are **header-only** — no new suppliers or utility
categories. They exist so `load_all.bat` finds a file and loads 0 rows instead of failing.

## The 2023 price rise — why it is here

Seven of the best-selling products get a price increase on **2023-01-01**:

| Product | 2022 | 2023 |
|---|---:|---:|
| Salicylic Acid Acne Cleanser | 42.00 | 48.00 |
| Vitamin C Brightening Serum | 89.00 | 98.00 |
| Retinol Renewal Serum | 110.00 | 125.00 |
| Peptide Firming Serum | 120.00 | 135.00 |
| Collagen Youth Cream | 95.00 | 108.00 |
| SPF50 Daily Sunscreen Lotion | 55.00 | 62.00 |
| Hydrating Sleeping Mask (Jar) | 72.00 | 82.00 |

The 2023 order lines for these products in this folder carry the new price; the **2022 lines in the
same folder still carry the old one** — the split is by order date, not by folder.
[99_price_increase_2023.sql](99_price_increase_2023.sql) applies the same change to the OLTP
`product` table.

That is what makes SCD Type 2 demonstrable rather than theoretical: after `maintain_product_dim_scd2
(DATE '2023-01-01')`, `product_dim` holds two rows per product, and because the fact load resolves
`product_key` by `order_date BETWEEN effective_start_date AND effective_end_date`, the 2022 lines
attach to the expired version and the 2023 lines to the current one — the same product reports two
different prices against the orders that actually paid each.

